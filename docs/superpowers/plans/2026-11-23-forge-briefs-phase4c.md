# Helper tiers and enforced briefs (Phase 4c) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agents bound to org model tiers with forge's four helper presets and a non-blocking lint, and a structured Brief on tasks whose CAN / CANNOT change co-guard enforces.

**Architecture:** Migration 0013 adds `guard_org_settings.model_tiers`, `agents.tier`, `tasks.brief`, `tasks.brief_bounds`. `app/tiers.py` owns the map, model resolution and the lint; `app/briefs/` owns validation, inheritance bounds, the prompt text and the policy scope. The worker puts the brief text in `--append-system-prompt` and the `brief` key (plus readonly roots for CANNOT folders) in the policy; `co_hook.py` denies file-tool changes outside the brief before the rules engine runs; shell writes into CANNOT folders are denied by the existing readonly-source rule.

**Tech Stack:** FastAPI, async SQLAlchemy, Alembic, pytest (SQLite + CI Postgres); co-guard hook (stdlib, `python3 -I`); React 18, antd 5, vitest.

**Spec:** `docs/superpowers/specs/2026-11-23-forge-briefs-phase4c-design.md`

## Spec deviations (resolved here)
1. **Not split into 4c/4d.** 8 tasks; tiers (Tasks 1, 2, 6) and briefs (Tasks 3, 4, 5, 7) share only the migration.
2. **Brief in the system prompt, not the user prompt** (the caller's "rendered into the run's prompt"): `prompting.compose` rewrites the stored prompt per row type and compaction drops conversation text; `--append-system-prompt` is re-sent on every step and survives compaction.
3. **Brief errors are 422 with a plain string `detail`:** the schemas take `brief: Optional[dict]` and `clean_brief` validates, so Pydantic's list-shaped errors never reach the user. Agent create/update keep their existing 400s for model/tier.
4. **Shell enforcement is partial and stated:** CANNOT globs that are a literal path or `<literal>/**` become readonly roots (`readonly-source`); other CANNOT globs and outside-CAN are file-tool-only (spec "Shell commands").
5. **Dispatched children get `brief_bounds`** (not in the caller's list): without it a coordinator under a brief could dispatch a child outside it.

## Review Focus
1. Escapes from a brief with file tools: `src/../migrations/x.py`, a symlink `src/link -> ../migrations`, an absolute path into CANNOT, `MIGRATIONS/x.py` on macOS, NotebookEdit / MultiEdit, a helper (`agent_id` set) → all denied; a Write to `/tmp/x`, to `$CO_TASK_DIR/handoff.md` or to another folder outside the project → not touched by the brief; Task 5.
2. A malformed `brief` key (a string, layers not a list, `can: "src/**"`, a non-str glob) and a crash inside the check → every file-tool call denied, never allowed; Task 5.
3. Shell into CANNOT folders: `echo x > migrations/a.sql`, `sed -i s/a/b/ migrations/a.sql`, `rm -rf migrations`, `cp a.sql migrations/`, `cd migrations && touch b` → denied with the brief reason; `pytest` / `npm test` in the project and `echo x > out.txt` outside CAN → allowed (documented); `**/*.lock` CANNOT → reported as file-tools-only; Task 4.
4. Inheritance and widening: follow-up, Continue, answer follow-up, guard follow-up and Duplicate keep the brief; a dispatched child without a brief takes the parent's; with its own it gets a bound, and a write its own CAN allows but the parent's CANNOT forbids is denied; a 6th nesting level → 422; Task 3 (rows) and Task 5 (layers).
5. Brief input edge cases: `stop: "Never."`, `"NEVER"`, `retries: true`, `"3"`, `-1`, `11`, `can_change: "src/**"` (a string), `["/etc"]`, `["../x"]`, a 31-wildcard glob, 21 entries, a zero-width-only goal, unknown key, `{}` → 422 with the exact plain reason; `brief: null` → no brief; Task 3.
